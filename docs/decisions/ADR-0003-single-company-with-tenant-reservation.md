# ADR-0003：当前单公司运行，保留 tenant_id 安全边界

* 状态：Accepted
* 日期：2026-08-04
* 决策迭代：DEV-20260804-001（后续需求修正）

## 背景

当前产品只服务一家公司，不需要租户选择、租户管理或套餐隔离。数据库早期已经使用 `tenant_id` 作为查询范围与唯一索引组成部分。

## 决策

登录不接收公司参数，由 `GAI_TENANT_DEFAULT_ID` 固定当前公司。后端 JWT、表字段、Repository 查询条件继续保留 `tenant_id`，用途是当前数据安全边界和未来低成本扩展位，不对用户暴露多租户产品能力。

## 结果

当前体验保持单公司简单模型，同时避免未来扩展时重写所有表和查询。代价是代码中仍存在 tenant 命名；文档必须明确它不是已交付的多租户功能。

## 回滚或替代

若确认永久单公司，可在 MAJOR 版本通过新 migration 移除字段；不得直接修改历史 migration。若未来启用多公司，必须新增权限模型、租户管理、跨租户安全测试和独立迭代，不得仅打开前端选择器。
