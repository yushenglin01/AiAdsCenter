# ADR-0004：运行时采用带校验值的前向 SQL Migration

* 状态：Accepted
* 日期：2026-08-04
* 决策迭代：DEV-20260804-005

## 背景

启动时使用 GORM AutoMigrate 无法稳定表达版本、回滚、审核和已发布 migration 不可变性，也无法检测历史 SQL 被覆盖。

## 决策

服务启动时先从 `000000_schema_migrations.up.sql` 引导历史表，再按文件名顺序执行 `migrations/*.up.sql`，记录文件名、SHA-256 与执行时间。已记录 migration 的校验值发生变化时启动失败。每个新变更必须新增成对的 up/down 文件；连历史表自身也不使用代码内硬编码 schema。

MySQL DDL 可能隐式提交，因此迁移按语句前向执行，失败后不得把版本写入历史表；运维人员需检查已执行到的语句，再通过新的修正 migration 恢复一致性。

## 结果

数据库结构变更可审计、可检测篡改并与发布记录关联。代价是必须严格设计幂等和部署顺序，不能依赖 AutoMigrate 自动修正模型差异。

## 回滚或替代

优先使用新增修正 migration 前向恢复。确需回滚时，在确认数据影响后人工执行对应 down 文件，并同步删除该版本的 `schema_migrations` 记录；不得自动回滚生产数据。
