# ADR-0001：MVP 采用 Go 模块化单体

* 状态：Accepted
* 日期：2026-08-04
* 决策迭代：DEV-20260804-001

## 背景

MVP 需要在单机 Docker Compose 中可运行、可演示，并覆盖认证、导入、指标、规则、Agent 与前端。此时拆分微服务会增加部署、事务、追踪和契约成本，却没有独立扩缩容证据。

## 决策

HTTP API 使用一个 Go 进程，按 `domain/repository/service/handler` 和业务模块组织；MySQL、Redis、Web 独立容器。Worker 保留独立入口，但在阶段五真正引入异步任务前不伪装队列能力。

## 结果

优点是本地演示简单、事务边界清晰、跨模块调试成本低。代价是模块必须坚持单向依赖和接口边界，否则会形成耦合单体。只有出现明确的部署、吞吐或组织边界时才评估拆分服务。

## 回滚或替代

业务模块已按包边界隔离，未来可优先抽离 ingestion 或 worker；在此之前不引入分布式事务。
