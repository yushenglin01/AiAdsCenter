## 实现内容

* 新增 `adnova.ingestion.batch` 1.0.0 JSON Schema，支持 AD_METRICS、MMP_METRICS、GAME_REVENUE、CREATIVE_METRICS。
* 新增统一 `ImportBatch` 服务和 `POST /api/v1/imports/batches`，HTTP 与 Kafka 共用标准化、校验、游戏解析、事实写入和批次幂等。
* 新增独立 `cmd/ingestion-worker`，支持多 Topic、consumer group、TLS、可选 SASL/PLAIN、手动 Offset 与优雅退出。
* 新增 MySQL Inbox：按租户/生产方/批次和 Topic/Partition/Offset 双重去重，载荷哈希冲突明确失败。
* 新增 DLQ：永久错误保存来源位置、错误分类、SHA-256 与 Base64 载荷；临时错误保留 Offset。
* 新增分析窗口：合并相同租户、游戏和日期范围的数据集，防抖后运行指标、规则、归因和素材确定性流水线。
* Docker 镜像加入 ingestion-worker；Compose 使用可选 `kafka` profile 接入外部集群，不内置 Broker。

## 安全与回滚

* Kafka Worker 固定 tenant/producer，并与每条消息交叉校验；不允许消息切换租户。
* TLS 默认开启；用户名与密码必须成对配置；日志不输出原始载荷或凭证。
* `REPLACE_RANGE` 只允许 MMP_METRICS，其他数据集只能追加去重。
* DLQ 含业务载荷，应使用与原 Topic 等级相同的 ACL、加密和保留策略。
* 停用 Kafka 配置可回退到 HTTP/文件导入；执行 down 前应导出 Inbox、DLQ 对应记录和分析窗口审计信息。
* 000012 的新增列均可空且新表不回填，但组合索引仍会扫描 data_import_jobs；生产前应按实际表量评估 DDL 时间与锁等待。
