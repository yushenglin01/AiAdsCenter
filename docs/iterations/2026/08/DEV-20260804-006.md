## 接口变更记录

### POST /api/v1/analysis/business

* 变更类型：执行语义和成功状态码变更。
* 请求变化：无；仍接收 game_id、campaign_id、analysis_date。
* 成功响应：HTTP 202，返回 TaskDetails；新任务通常为 PENDING/QUEUED，幂等任务可能已是终态。
* 失败响应：401、403、422 与 500 边界保持。
* 兼容性：JSON 响应结构向后兼容新增字段，但依赖 HTTP 200 或同步完成的客户端必须升级。

### GET /api/v1/analysis/business/tasks/:id/events

* 变更类型：新增。
* 成功响应：HTTP 200 `text/event-stream`，`task` event 携带 TaskDetails；终态后关闭。
* 失败响应：401 或租户范围内 404。
* 兼容性：向后兼容新增端点。

### GET /api/v1/analysis/business/tasks/:id/report

* 变更类型：新增。
* 成功响应：HTTP 200，返回 READY AnalysisReport。
* 失败响应：401；报告不存在或跨租户统一 404。
* 兼容性：向后兼容新增端点。

## 风险与注意事项

* Asynq v0.26.0 公共 API 仍是 v0，依赖升级需跑完整队列契约与离线恢复测试。
* 当前 SSE 是数据库轮询快照，适合 MVP；高并发前需评估连接数与查询频率。
* Outbox PUBLISHED 表示进入 Redis，不代表业务成功；运维必须同时监控 Outbox、Asynq 和 agent_tasks 终态。
* 000006 已发布后不得原地修改，只能新增 migration。

## 回滚方案

1. 禁止新的经营分析提交，停止 Worker，记录所有 PENDING/RUNNING/RETRYING 任务。
2. 备份 task_outbox、analysis_reports 及 agent_tasks 新字段。
3. 部署 0.4.1 API/Web，并确认不会再启动 0.5.0 Worker。
4. 经变更审批执行 000006 down，删除 000006 对应 schema_migrations 记录。
5. 运行 0.4.1 的 Go/前端/Compose/E2E 验收；确认同步端点恢复 200。

回滚影响：所有未完成异步任务、Outbox 状态与报告快照会丢失；已生成建议/发现仍需在回滚前明确保留或清理策略。
