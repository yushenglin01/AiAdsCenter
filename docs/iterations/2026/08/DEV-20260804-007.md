## 接口变更记录

### GET /api/v1/recommendations 与 /recommendations/:id

* 变更类型：新增。
* 请求：列表支持 status、action、risk_level、limit。
* 成功：200，返回建议、审批、广告计划名、任务状态和报告关联。
* 失败：401；详情跨租户或不存在返回 404。
* 兼容性：向后兼容新增。

### GET /api/v1/approvals 与 /approvals/:id

* 变更类型：新增。
* 请求：列表支持 status、action、limit。
* 成功：200，返回审批、建议、任务、报告和广告计划。
* 失败：401/404。
* 兼容性：向后兼容新增。

### POST /api/v1/approvals/:id/approve

* 变更类型：新增。
* 请求：`comment` 可选，最长 1000。
* 成功：200；approval=APPROVED、recommendation=APPROVED，最后一张审批完成时 task=SUCCEEDED。
* 失败：400 请求无效；403 角色/自审批；404 不存在或跨租户；409 非 PENDING/并发冲突。
* 副作用：同事务 audit_logs 追加 APPROVAL_APPROVED；不调用广告平台。

### POST /api/v1/approvals/:id/reject

* 变更类型：新增。
* 请求：`comment` 必填，最长 1000。
* 成功：200；approval/recommendation=REJECTED。
* 失败和审计：同 approve，成功 action=APPROVAL_REJECTED。

### GET /api/v1/model-usage 与 /summary

* 变更类型：新增；仅 ADMIN/MANAGER。
* 成功：200，返回明细或调用/Token/成本/延迟/Provider 汇总。
* 失败：401/403。

### GET /api/v1/audit-logs

* 变更类型：新增；仅 ADMIN。
* 请求：action、resource_type、actor_id、task_id、limit 筛选。
* 成功：200；租户范围内审计事件。
* 失败：401/403。

### GET /api/v1/dashboard/operations

* 变更类型：新增。
* 成功：200；待审批、任务、成功率、模型调用/成本和审计数量。
* 失败：401。

## 风险与注意事项

* audit_logs 当前由应用保证追加，数据库管理员仍可修改；不能表述为法规级不可篡改。
* WAITING_APPROVAL 表示分析和报告已完成，但工作流尚未收口；客户端不可把它显示成失败。
* 批准仅把 recommendation 标记 APPROVED，人工是否执行在系统外，当前没有执行回写。
* 000007 发布后不得修改，只能新增 migration。

## 回滚方案

1. 停止新分析与审批，停止 Worker，导出 WAITING_APPROVAL、approval_requests、recommendations 和 audit_logs。
2. 处理已经部分人工决策的业务单据，明确回退后的展示状态。
3. 经审批执行 000007 down 并删除对应 schema_migrations 记录。
4. 部署 0.5.0 API/Worker/Web，确认旧任务详情仍可读取。
5. 运行 0.5.0 的 Go、前端、Compose 和 Stage5 E2E。

回滚影响：审计事件、审批原因/风险/报告关联和 decision_version 会丢失；WAITING_APPROVAL 任务不会由 0.5.0 自动处理，必须在回滚前人工迁移为可识别状态。
