## 实现内容

* analysis_windows 新增 locked_until 与内部 claim_token；PENDING 窗口和租约过期的 PROCESSING 窗口均可原子认领。
* 完成与重试必须匹配版本和 claim token；新批次提升版本或其他 Worker 重新认领后，旧执行不能覆盖当前状态。
* 新增 `GAI_KAFKA_ANALYSIS_LEASE`，默认 15 分钟；与消息 Inbox lease 分开配置。
* 金额类字段按 DECIMAL(20,6)、frequency 按 DECIMAL(12,6) 在入库前校验非负、范围和小数精度。
* 标准批次 JSON Schema 同步声明数值上限、6 位小数与 frequency 独立范围。

## 安全与回滚

* 租约只解决执行权恢复，不允许跨租户认领；窗口仍由 tenant_id、game_id、period 唯一隔离。
* down migration 会删除租约和 claim token；回滚后 PROCESSING 窗口不再具备自动崩溃恢复，应先停止 ingestion worker 并确认没有在途分析。
* 生产环境的 analysis lease 应大于确定性流水线的高分位执行时间；当前默认 15 分钟，真实数据量上线前仍需压测校准。
